# Capability matrix: account-rotation

Light-form design (Phase 1 of `/planning:design`), 2026-09-04. Inputs: the confirmed Brief in
`../PLAN.md`, spikes 01 to 04 (memory slice), the research root index, and the org standards
(`melodic-software/standards`, `conventions/engineering/*` and `conventions/review/*`).

One executable, one operator, one machine at a time. Every capability below is app-specific; none
is shared-library-worthy yet (the org's `simpler-code.md` forbids extracting an abstraction before
a second consumer exists). The only cross-repo surface is the tee `account` field, which lives in
`rate-limit-guard`, not here.

| # | Capability | Domain concepts | Invariants | Storage | Reuse |
|---|---|---|---|---|---|
| C1 | **Identify the live account and the parked ones** | live config dir, state file `oauthAccount` block, profile folder, `profile.json`, roster entry | Identity comes from `profile.json` or `claude auth status --json`, never from a folder name. A profile folder holds at most one `.credentials.json`. The live account's folder in the profiles root holds none while it is live | reads `~/.claude/.credentials.json`, `~/.claude.json` (or `<CLAUDE_CONFIG_DIR>/.claude.json`), `~/.claude-profiles/<folder>/{.credentials.json,profile.json}` | app-specific |
| C2 | **Switch the machine to a parked account** (model D) | switch plan, park, unpark, refresh lock, refusal | Pairs are moved, never copied. Exactly one file holds a given refresh token after any switch. Only the `oauthAccount` block of the state file changes. A switch refuses while a fresh `*.lock` (not `daemon.lock`) sits in the live dir, when the target is the live dir, when the target's refresh token equals the live one, or when the target has no pair. Every file write is temp-file, flush, rename | same files as C1 | app-specific; behavioral reference is `spike-04-swap.py` |
| C3 | **Read quota for every account** (three tiers) | usage snapshot, `limits[]` entry, quota source, capture time, rate-limit lockout, refresh budget | Tier 1 reads the statusline tee file. Tier 2 makes one usage read per non-paused account per Refresh all, spaced about one second apart, never more than 6 reads per account per rolling 5 minutes, honoring `Retry-After`. On 401 the parked pair is refreshed once and the read retried once. No timer ever calls the endpoint. Cards render from `limits[]` only; codenamed top-level buckets are never referenced by name. Every request carries the tool's own User-Agent | reads `~/.claude/rate-limit-guard/rate-limits.json`; caches the last snapshot per account under app data | app-specific; behavioral reference is `spike-usage-probe.py` and `spike-02-rate-bucket-probe.py` |
| C4 | **Refresh a parked pair's credentials** | token refresh, rotated refresh token, `refreshTokenExpiresAt`, atomic write-back | Only parked pairs are refreshed; the live pair is never refreshed by this tool (a session may be refreshing it). The new `refreshToken`, `accessToken`, `expiresAt`, and a recomputed `refreshTokenExpiresAt` (from `refresh_token_expires_in`) are written back atomically to the parked file only. On any HTTP error the file is untouched | `~/.claude-profiles/<folder>/.credentials.json` | app-specific; behavioral reference is `spike-03-credential-refresh.py`, including its one defect (it left `refreshTokenExpiresAt` stale) |
| C5 | **Rank accounts and propose switches** | eligibility, deadline (`seven_day.resets_at`), headroom, ranked queue, switch proposal, switch-back cooldown, urgency flag, routing policy | Eligible = not paused, 7-day used under 100, 5-hour used under 90. Order by earliest weekly reset. Propose a switch when the active account trips or crosses 90. Propose a switch-back at most once per 30 minutes. Flag accounts whose weekly reset is within 24 hours and still hold headroom. Queue shows the next three. All numbers are settings. A proposal is advice; only a human click switches | routing policy in `config.json`; last proposal time in app-data state | app-specific, pure |
| C6 | **Maintain the roster** (add, pause, remove, alias, browser mapping) | roster entry, folder name sanitization, paused flag, browser kind, browser profile directory | Folder name = lowercased email with `< > : " / \ \| ? *` and control characters replaced by `_`, trailing dots and spaces trimmed. Add creates the folder and offers Login. Pause removes from the queue, not the page. Remove deletes the folder after an optional logout. The live account may be adopted into the roster from the live state file | `roster.json` under the per-user app-data dir | app-specific |
| C7 | **Assist a browser login for a parked account** | login session, sign-in URL, mapped browser profile, one-time code, callback | Login runs the unmodified `claude` binary with `CLAUDE_CONFIG_DIR` pointed at the profile folder; the tool never performs OAuth itself. The URL is opened in the roster's browser and profile. A completed login leaves a valid pair in the folder. The tool ignores every other file the login leaves in the folder and may prune them | profile folder | app-specific |
| C8 | **Serve the dashboard** | card, queue, proposal, action buttons, source and capture time per card, login expiry per card | Loopback only. Mutating requests require the app's own origin. No token or credential content ever reaches the page or the logs | none (static page embedded in the executable) | app-specific |
| C9 | **Configure without editing code** | configuration file, defaults derived from the user profile, config template, first run | Every path, port, threshold, and browser mapping lives in one config file. Defaults never contain a drive letter or a user name. First run creates the file from the shipped template | `config.json` under the per-user app-data dir | app-specific |
| C10 | **Attribute statusline snapshots to an account** (tee change, other repo) | `account` field in the tee file | The tee writes `account.email` from the live state file's `oauthAccount` block with no new process on the render path; the reader contract documents the shape, and its untrusted-value rule already covers it | `~/.claude/rate-limit-guard/rate-limits.json` | lives in `rate-limit-guard` (claude-code-plugins), separate PR |

## Out of scope by Brief

Automatic switching, timer polling, two live accounts, macOS Keychain, Enterprise seat rotation,
promotional credits, any proxy or model-API call. Post-V1 candidates: `StopFailure` hook ping (Q27),
tray icon and notifications (Q28).
